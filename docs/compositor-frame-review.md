# フレーム配信での限定再確認

通常モード、PC1280/390/320pxで「ガチャ100連→10連切替」「戦闘結果→元キャラ育成」の2経路を確認。既存Chrome CDPのPage.startScreencast（PNG、everyNthFrame=1、最大横640px）で即時ACKし、取得後に画像解析した。新規ソフトやOS設定変更なし。

調整前と比較用CSS注入後の12記録、計394枚。一時的な全面白化・前後の静止状態を超える白ピークは未検出。画像列も確認。これはブラウザが配信した合成画像であり、全画面リフレッシュを無損失録画する機能ではない。

- 連数切替：各37〜39枚、間隔中央値45〜46ms、最大58〜61ms。
- 育成復帰：各27〜29枚、間隔中央値11〜13ms、最大48〜633ms。最大の画面変化を挟む間隔は29〜59ms。静止画面で配信されない区間とフレーム落ちを完全には区別できない。
- 16.7msの全フレーム観測ではなく、短い白化を完全に除外できない。実GPU／実スマホについても保証しない。

## 根拠のある局所調整

PCの結果→育成の持続的な平均linear輝度差は約+0.413、画素輝度+0.35以上の面積は68.1%。結果ダイアログのbackdropだけをrgba(16,41,71,.16)、blur3pxにすると差は+0.176、面積36.7%へ減った。

小画面では元の輝度差が小さく、同じ変更が逆方向の差を増やすため適用しない。実装は651px以上の戦闘結果ダイアログ背景だけ。不透明な結果パネル・文字色・育成背景・ボタンのぷにぷに反応・アニメーション・保存計算は不変。新しいfadeや待ち時間は追加しない。低モーションでも同じ配色。
